# 开发与发布

仓库保留rime默认词库和源码，安装不依赖开发引擎或全量数据。首次源码检查可运行 `python tests/install_test.py`：只使用临时假用户目录，不操作真实Rime配置。

## 构建与可选验证

要重新生成**默认正式词典**，使用 `python tools/build.py --source rime/booru.tsv`。不带--source的历史入口用于260条演示bootstrap，会覆盖正式输出，不应用于正式包。转换与构建前保存已有版本。

全量处理需要恢复Release数据包中的dictionary目录，并安装固定转换依赖：`python -m pip install --target tools/pydeps pypinyin==0.55.0`，之后运行 `python tools/convert_dictionary.py`。来源commit及SQLite校验见《词库交付说明》与数据包source.json。dictionary、pydeps始终被Git忽略。

`tests/engine_test.py`是可选原生集成检查，需要自行准备官方Windows x64 librime及配套头文件，放到tools/librime/dist，或用BOORU_RIME_DIST指定路径；测试的进程内存记录还使用psutil。设BOORU_TEST_LIMIT=48可限制样本数；测试用户目录默认在validation/gpt/runtime，与真实Rime用户目录分开。本仓库不捆绑原生开发运行时；它们的许可证按实际分发内容另行保留。

`tests/comfy_smoke.py`会向本机ComfyUI提交一次生成任务，不属于默认测试，不应未经使用者同意运行。实际应用输入、反复比图按人工验收清单由维护者执行。

## 打包与内容边界

旧版本附件和全量/引擎开发资料保留在本地仓库外，公共仓库不记录个人机器归档路径。`tools/package_release.py`需要dictionary、validation/gpt/formal-*-engine.json及validation/gpt/full-build/rime；干净clone不自带这些数据和验证结果。准备好后可运行 `python tools/package_release.py --artifacts-root <本地数据根目录> --output-dir <新附件目录>`，直接读取仓库外的资料，无须移动原归档。省略参数时均使用仓库内的默认目录。打包只读取已有PASS报告，不重新运行引擎验收。

自有代码已采用MIT；0.2.0已完成维护者本机实机验收，README明确未附实机截图。每次发布先审核文案和许可，再重建两个独立EXE、三个ZIP与SHA256SUMS.txt，检查ZIP CRC及包内文件哈希；保留来源、覆盖与异常记录。旧附件的内容不会随仓库提交自动更新。

0.2.1默认与扩展包附带原生独立 `安装绘画提示词.exe`，另提供可单独下载的 `*-setup.exe`。方案及对应词库通过Go的embed内置，安装、备份、回滚直接在进程内执行，不启动Python或其他子进程；用户无需Python、.NET或Go，安装无需联网。目标为Windows 10/11 x64，EXE仅进入Release附件，不进入Git。源码入口 `tools/install.py`继续保留。

原生安装器源码位于 `tools/windows-installer/`。开发者使用Go 1.23或更新版本构建，运行 `python tools/build_windows_installer.py --go <go.exe路径> --output <输出EXE路径> --test` 可测试并构建默认词库；`--source <rime目录> --variant searchable`指定扩展词库。编译时设置CGO_ENABLED=0，禁用模块下载并移除本机源路径；只使用Go标准库。编译器仅供开发者使用。

三套附件的打包命令增加 `--go <go.exe路径>`，会同时生成两个独立EXE、三个ZIP及SHA256SUMS.txt。Go运行时许可和PATENTS声明保留在licenses目录，并内置于独立EXE，可用 `--license`查看。

新安装器测试：`python tests/native_installer_test.py --exe <独立EXE路径> --source <对应rime目录>`。测试在临时目录中把EXE单独复制、清空PATH，检查安装、回滚、内置词库字节一致性、中文/空格路径、BOM/CRLF、备份链、双向兼容Python备份，以及配置/手工修改冲突时不写入；不操作真实Rime用户目录。Rime方案和词库未改变时沿用0.2.0引擎测试证据，不将安装器自动测试冒充新的小狼毫实机验收。

源码Git不跟踪ZIP、引擎DLL/PDB/7z、词库中间产物、日志或Python缓存；大文件经批准后上传GitHub Release附件，避免进入Git历史。详细审批项见《发布检查清单》。
