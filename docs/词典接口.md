# 正式词典接口 v1

状态：第1步已定；适用于挂载小狼毫的 booru 方案。生产目录为项目根目录下 `dictionary/`，生成物由 GPT 整合至 `rime/`。全量转换由 GPT 直接承接，DeepSeek无需清洗或搬运数据。本文件定义交付契约，尚不表示正式词库已生成。

## 1. 文件与字段

`entries.tsv`：UTF-8无BOM、LF换行、制表符分隔，第一行必须依次为 `tag`、`zh`、`code`、`weight`，仅此四列，不把category加入此文件。禁止空行、额外列及字段内TAB/CR/LF/NUL；字段首尾空白在清洗阶段去除。一个中文别名/读音映射一行。

| 字段 | 含义与取值约束 |
|---|---|
| tag | 来源的规范英文标签名，非空；原样保留大小写、数字、下划线及合法标点，禁止自动翻译、改空格或改大小写。重命名只允许有来源证据的显式映射。括号转义与末尾逗号属于上屏层，不存入本字段。 |
| zh | 非空中文释义或单个别名；可包含数字/拉丁字母，不要求纯汉字。来源释义原文另存；不能无依据拆分括号、斜线或逗号产生别名。 |
| code | 正则 `^[a-z]+$`；连续小写无声调拼音，ü归一为v；不是英语tag的拼写。含数字/外文字母的释义须按下一节处理。 |
| weight | 十进制整数0–10000，无符号、无小数。仅表示候选优先级，大者优先；不是正确率、模型支持度或绘画权重。0保留为最低优先级。 |

最小样例（下表文件块使用真实TAB，可直接存为TSV）：

```tsv
tag	zh	code	weight
twintails	双马尾	shuangmawei	10000
thighhighs	过膝袜	guoxiwa	10000
white_hair	白发	baifa	10000
white_hair	白头发	baitoufa	10000
white_hair	白毛	baimao	10000
```

## 2. 拼音、别名与歧义

1. 以完整词组生成读音，不逐字穷举多音字笛卡尔积；固定工具名称、版本和词组覆盖表。优先级：项目人工覆盖 > 明确词组读音 > 工具默认读音。自动结果在元数据标为 `auto`，不冒称人工确认。
2. 读音先转小写；有声调的Unicode拼音去调号但保留ü语义，再将ü或u:转v；数字调号1–5仅可在“拼音音节输入”中去除，不对中文原词数字直接删除。输出去除音节间空格/撇号，最终验证 `[a-z]+`。例如：绿色→lvse，女孩→nvhai，长发→changfa，行走→xingzou；不能把ü错误变为u。
3. 数字、英文缩写、符号、无法识别汉字不得直接丢弃。只有显式别名/读音覆盖可转换（如1girl的中文别名“女孩”→nvhai）；其余保留在全量规范化数据，记异常，不进入可检索TSV。
4. 确认存在多种读法时保留多个code并记录依据；工具报未知、多读音冲突或明显语义冲突时，记录 `ambiguous_pinyin`，待覆盖后再输出，不能猜一个说已解决。默认词组读音不构成“所有歧义已核验”。
5. 同一个tag可有多个中文别名；同码异tag全部保留候选。相同 `(tag, code)` 只输出一行：取最大weight；zh按“人工首选 > 来源主释义 > 别名”，同级按Unicode字典序选定，其他释义留在元数据。规范英文tag相同不代表中文别名可跨不同tag合并。

## 3. 分类、排序及完整性

分类沿用来源的Danbooru编号，存入元数据/SQLite，不扩充TSV表头。

| category | 类别 | 默认策略 |
|---|---|---|
| 0 | general／一般标签 | 常用精选候选池 |
| 1 | artist／作者 | 全量保留，单独分类 |
| 3 | copyright／作品 | 全量保留，单独分类 |
| 4 | character／角色 | 全量保留，单独分类 |
| 5 | meta／元数据 | 全量保留，单独分类 |
| 其他/缺失（含2） | 未知 | 保留原值、记unknown_category，暂不导出至加载词库 |

源post_count须为非负整数；来源缺失或非法则记异常，排序临时按0处理，不伪造来源计数。默认weight为 `min(9999, 1 + floor(1000 * log10(1 + post_count)))`；人工核心词覆盖可设10000，必须有覆盖记录。帖子数只作热度代理，不保证适用于SDXL/Pony。

TSV最终按 `code升序、weight降序、tag升序` 稳定排序；同码同权重的实际UI顺序不承诺与文件一致，由维护者验收。0.2.3起filter对同tag展示booru.tsv中最高weight行的zh（同权重保留首次出现者），因此别名检索可能展示另一中文主释义；不能把别名全部显示当作已实现。

完整数据与默认加载区分：所有来源记录进入规范化SQLite；合法可检索映射进入全量entries.tsv；精选文件另命名 `entries.common.tsv`，不得把筛选后数据冒称全量。必须报告原始记录数、独立tag数、映射数、重复合并数、异常记录数、无可用映射tag数及各分类数量；映射可一对多，不能直接要求输入行数等于输出行数。用tag集合核对覆盖与缺失，每个缺失tag必须可追溯原因。

## 4. 元数据与异常格式

`metadata.jsonl`：UTF-8，每行对象含 `tag, category, post_count, source_zh, aliases, pinyin_status, source_ref`；aliases为对象数组，每项含 `zh, code, origin`，origin为source/manual，pinyin_status为auto/reviewed/pending。SQLite使用 `tags(tag主键, category, post_count, source_zh)` 与 `aliases(tag, zh, code, weight, origin, pinyin_status)` 两表，aliases以 `(tag, zh, code)` 唯一，tag引用tags。未解决读音的code允许NULL，TSV不允许。

`exceptions.jsonl`：每行固定键 `source_ref, source_row, tag, field, raw_value, reason, action, detail`；source_row为来源表主键或行号字符串，未知tag用null。reason枚举：empty_tag/empty_zh/invalid_field/invalid_count/unknown_category/unsupported_text/ambiguous_pinyin/duplicate_merged。action枚举：quarantine（不上屏，保留源记录）/fallback_count（计数按0）/merged（留元数据）/needs_review。detail写具体原因；不得仅记“失败”。同一tag可有多个异常，异常行数不等于缺失tag数。

## 5. 更新、来源与验收交接

- `source.json`记录仓库URL、固定commit、下载UTC时间、SQLite及LICENSE的SHA-256、实际表名/字段、来源记录数、工具及依赖版本、接口版本v1；不以“每日更新”代替固定版本。不执行来源库内代码，只读数据表。
- 原始快照放 `dictionary/source/<commit>/`；手工别名/读音覆盖独立放 `dictionary/overrides.tsv`（同四列），理由另放覆盖记录。来源更新不能覆盖人工表；临时词库中核心样本先保留为显式覆盖，逐项标明非来源原文。
- 新来源先在暂存目录转换、核对增删/异常及核心样本，再生成候选发布版本；保留上版manifest、词库与差异记录，批准发布前不替换已交付包。禁止自动向用户Rime目录更新。
- 构建入口沿用 `python tools/build.py --source dictionary/entries.tsv`。当前构建器只保证基本字段检查、去重及导出；分类、读音、来源及异常核对由第2步转换器完成，不能把它们声称为现有build.py能力。
- 我们只做必要静态检查和一次可完成的自动化检查；反复输入、逐项比图与真实小狼毫验收交老板，见《人工验收清单》。待老板装好前不读写其Rime用户目录。

来源字段/分类参考：[ffdkj README](https://github.com/ffdkj/ffdkj-Danbooru_Tag-Chinese-English-Translation-Table#readme)；下载时再次对照实际SQLite结构，若字段不一致先报差异，不静默猜表。

## 6. 0.2.2项目通用短语层

以上规范标签与来源统计仍适用于ffdkj数据。新增通用颜色表达由`data/general_colors.tsv`及`tools/general_phrases.py`单独维护，不写回上游快照或来源归档，不计为来源tag。运行时TSV沿用四列结构，通用行的tag字段是`__prompt__:`加英文表达的内部键，zh以“〔通用短语〕”结尾；这类内部键不按上游规范标签解释，也不能原样上屏。Lua过滤器去掉前缀后按当前分隔设置输出，并保留通用类型标识。原始快照保持不变；生成运行库可合并同码同英文的内部键，保证原有检索/英文输出覆盖。

0.2.3补充层用 `data/imported_terms.tsv.gz` 六列中间接口：tag、zh、code、weight、scope、source。默认仅加载scope=default，扩展加载全部。构建后仍为四列运行时接口；新增短语私有前缀在Lua上屏前删除，原ffdkj标签行保留。来源合并统计见library_sources.json。

当前生成层按(code, 去掉私有前缀的最终英文)合并完全重复项，不更改英文大小写、下划线、标点或词义。先保留原同内部键处理顺序，再仅对不同内部键导致的输出重复取最大weight，同权重优先带维护类别的zh；有规范来源键时保留该键。原始来源和合并审计不删除。
