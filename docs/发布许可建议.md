## 可选的自有代码许可

| 选项 | 对后续使用与分发的影响 |
|---|---|
| MIT | 允许商用、修改及再分发；保留版权与许可声明；不强制公开修改源码。适合希望别人方便复用方案和脚本的目标。 |
| Apache-2.0 | 同样允许商用、修改及分发；包含明确的专利许可/终止条款，并要求保留声明、标记修改，适用时处理NOTICE。若需要明确专利条款可选，文件维护比MIT多。 |
| GPL-3.0 | 对受覆盖作品的分发有同许可及对应源码义务；适合希望派生分发也保持相应自由的目标。不能据此重新授权本来独立的第三方词库。 |
| 暂不授权公开复用 | 保持自有代码LICENSE未定，不提供一般复用授权；即使以后把源码设为公开，也不能宣传为已按MIT等许可开源。最合适的当前动作是继续本地审核，选定后再公开。 |

建议：若目标只是便于用户安装、社区改词库/脚本，可以优先考虑MIT；这里只给建议，不代维护者选择。参考各许可证原文：[MIT](https://opensource.org/license/mit)、[Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0)、[GPLv3](https://www.gnu.org/licenses/gpl-3.0.html)。
