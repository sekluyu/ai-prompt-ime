# 项目手册

## 项目与交付

AI Prompt IME是挂载于Windows小狼毫（Rime）的离线提示词输入方案。用户输入无声调中文拼音，选取英文标签或项目维护短语。需要先安装小狼毫；普通用户使用独立EXE，无需Python、Go、.NET、API key或联网。

公开稳定版本以GitHub Release及对应标签为准。当前版本为v0.2.6，维护者已完成本机输入检查、确认本轮EXE火绒扫描未发现风险并同意发布。候选审核、维护者同意、上传和公开附件校验全部完成后，才记升级完成，最终结果以发布交接记录为准。完整词库为唯一默认，不分小词库版和扩展版。

## 核心文件

| 路径 | 用途 |
|---|---|
| rime/booru.schema.yaml | 方案、开关和Rime检索配置 |
| rime/booru.dict.yaml | 原生三列词典；weight是构建优先级 |
| rime/booru.tsv | tag、zh、code、weight、role五列；weight保留原热度 |
| rime/lua/booru_filter.lua | 按实际入口显示中文、英文去重、转义和分隔符 |
| data/general_prompts.tsv | 通用质量、材质等维护短语 |
| data/general_colors.tsv | 颜色和配色生成来源 |
| data/slang_aliases.tsv | 已明确维护的俗称检索入口 |
| data/pose_phrases.tsv | 躯干姿态、单手与常用双手动作 |
| data/imported_terms.tsv.gz | 固定上游词表的离线转换数据 |
| data/library_sources.json | 上游提交、文件校验值和许可记录 |
| tools/general_phrases.py | 合并项目维护层与导入层 |
| tools/build.py、tools/ranking.py | 全库重建及原生词典排序 |
| tools/build_windows_installer.py | 生成标准ZIP资源并编译独立EXE |
| tools/windows-installer/ | 仅依赖Go标准库的安装与回滚实现 |

## 行为约定

Rime先区分完整匹配与剩余补全长度，同等匹配下主词优先、按中文说明分组、组内原热度辅助。原热度与编译权重不可混淆。只合并同拼音同最终英文；相近意思、空格/下划线差异和狐狸等宽泛别名继续保留，不重建已撤销的问题。

选词默认追加英文逗号及空格。Ctrl＋Alt＋F9仅切换自动分隔空格，逗号保留；短语内部标点不重写。姿态片段可分别选取左右手，也有少量完整配对；没有自由文本翻译、任意语句解析、自动判断提示词正负框或跨词状态机。

## 修改与重建

1. 在对应维护TSV中添加英文、中文、拼音及类别；姿态词见《姿势与双手动作》。避免直接手改生成词典。原始ffdkj、e621等来源快照不改写。
2. 核对版本：build.py的词典头、schema版本、Go安装器版本及package_release.py版本一致。公开文档不要把候选写成已验收或已发布。
3. 使用完整运行库为基础重建：`python tools/build.py`，默认读取现有rime/booru.tsv；也可显式使用`--source <TSV>`。验证构建时加`--output-dir <隔离目录>`；演示数据仅通过`--demo --output-dir <独立目录>`生成，不允许写入项目rime目录。不使用历史小范围variant作为公开第二版本。
4. 运行与改动相关的数据检查。`python tests/pose_phrases_test.py`对照v0.2.5标签验证姿态覆盖；`python tests/ranking_slang_test.py`对照v0.2.3旧基线并允许明确的项目维护入口，检查原生排序。
5. Lua模拟检查：先设置`BOORU_RIME_DIST`指向自备librime的dist目录，再运行`python tests/lua_filter_test.py`。它不创建真实Rime会话、不发送按键。引擎和DLL不随源码交付。
6. 独立EXE：`python tools/build_windows_installer.py --go <go.exe> --source rime --output <EXE路径> --test`。随后用`python tests/native_installer_test.py --exe <EXE路径> --source rime`仅在临时目录检查安装、回滚和内置数据。

安装器以确定性、未加密的标准ZIP内嵌方案与许可，使用Go标准库读取，并在写入用户目录前读取管理资源。错误ZIP和CRC损坏拒绝安装。不调用外部解压器、不下载程序、不重启小狼毫，也不自动重新部署。

## 验收与发布

每次数据或二进制变化都重新记录哈希。旧引擎报告仅作baseline，不能冒充新版本输入验收；旧版本火绒扫描结果不能当作新EXE结果。真实输入、网页快捷键、图像姿态及火绒明确扫描由维护者确认。

交付一个独立EXE、含相同EXE的方案ZIP及SHA256SUMS.txt。`package_release.py --installer <已验收EXE>`核对并复用同一EXE，默认不生成追溯包，也不读取原始dictionary目录；仅需重建追溯包时增加`--include-dictionary`及来源参数。检查ZIP CRC、完整内部校验清单、包内与独立EXE一致性。原始数据追溯包可复用明确标注的历史版本，本轮不无故重新打包固定原始数据。

向维护者提供候选、变更说明、验证范围和将推送的文件清单；得到发布同意后提交、打版本标签、push并创建Release。附件全部上传并验证后公开，公开下载哈希与本地一致才宣布发布完成。若发布前更换EXE，需重新核对扫描与验收，不能沿用上一文件的结果。

## 维护边界与清理

仓库仅保留源码、维护数据和生成方案。全量dictionary、原始SQLite、引擎DLL/PDB/7z、pydeps、临时validation、发布EXE/ZIP、日志和机器路径报告都不提交；提交前核对git status和git ls-files，保护密钥。

保持现有Git标签作为版本依据，不新增手工全项目或词库备份。测试大文件和重复候选优先移入回收站，保留小型复现源码、校验值和有效证据；共享工具链与用户数据不按临时垃圾处理。真实Rime目录和小狼毫安装目录未经维护者指示不改动；项目外备份目录严格遵守已有范围限制。
