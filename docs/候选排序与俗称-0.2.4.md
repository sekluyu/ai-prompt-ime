# v0.2.4：候选排序与俗称检索

状态：v0.2.4基础更新，提供源码、独立EXE及含同一EXE的方案ZIP。以GitHub v0.2.3为数据基线，不新增手工项目备份，不改变现有本机安装。

## 排序规则

Rime的原生表检索先比较是否完整匹配，再比较补全剩余码长，最后比较权重。[实现参考](https://github.com/rime/librime/blob/1.13.1/src/rime/dict/dictionary.cc#L60)。本项目在构建时把以下顺序编码为原生词典权重：

1. 明确主词在前，来源扩展/未确定主次项在后。
2. 同层按中文说明分组；组位置用组内最高原热度决定。
3. 同一中文组内按原热度降序，同分按内部键/拼音稳定排列。

主词来自现有项目维护词、规范ffdkj入口及本轮明确的俗称映射；扩展资料未逐项人工判断，不因其热度高、英文短或带下划线就认定主词。迁移旧四列TSV时，使用v0.2.3保留下来的无私有前缀规范入口作为主词来源；新五列中明确保存角色，不在每次重建重新猜测。

原热度保存在booru.tsv的weight列，没有被编码值覆盖。booru.dict.yaml中的weight是编译后的全局顺序号；数值代表排序，不是新的来源热度。直接主词可在同码下超过更热门的宽泛别名，例如huli的fox和nursing在扩展狐种/角色前面。

同中文别名或不同英文输出没有被合并。384组空格/下划线写法和狐狸等原有泛称仍保留，排序不代表它们的释义已经修正。

## 注释与性能

运行时按内部词条键与具体拼音查询中文说明；补全通过Rime给出的剩余码查同一个索引。标签与部位标识保留，主词直接展示命中中文，扩展项有可靠主释义时附在后面，例如狐狸 · 耳廓狐。没有可靠主释义时沿用已有说明，不猜译。

索引启动时加载一次；每次候选做直接查表，不扫描全词库或一次性收集全部补全候选，保留原生按需分页。未完成前缀仍沿用Rime分批补全，不预读全部匹配项做全局重排。英文完全重复仍只显示一次，不跨查询保存seen状态。

## 检查与验收

ranking_slang_test以git show读取v0.2.3基线到内存，不落新的全库备份；检查所有原组合保留、仅新增四个预定组合、未相关原热度不变、主词优先、中文组连续和词典权重一致。

lua_filter_test只运行模拟候选：检查实际命中中文、补全剩余码、分段偏移、五列解析、字面引号和俗称注释，同时回归去重、空格/纯词模式及转义。不创建Rime会话或发送按键。

本轮在维护者关闭火绒后完成Go单元测试及最终EXE隔离安装/回滚，不代表安全软件兼容已解决。不操作真实用户目录；实机输入、翻页、网页热键与主观响应速度由维护者验收。安全软件兼容问题留待v0.2.5。
